# Portfolio pitch

## 30-second version

I built a privacy-first public-health analytics MVP that uses synthetic aggregate prescribing and public-health indicators to rank regional prevention-prioritisation signals. It includes a pandas data pipeline, transparent feature engineering, interpretable scoring, a Streamlit and Plotly dashboard, tests and governance documentation.

## Recruiter summary

This is a compact healthtech portfolio project designed to show that I can move from a healthcare problem frame to a runnable product prototype. The work demonstrates clinical-pharmacy awareness, data/AI product judgement, privacy-first design and practical Python delivery without crossing into unsafe clinical decision support.

## Why it matters

Population-level signals can help public-health, pharmacy and primary-care teams think about prevention planning when the data is aggregated, governed and clearly limited. This demo shows how such a workflow could be prototyped responsibly using synthetic data while making the assumptions visible.

## What the project demonstrates

- Python package structure with small, testable modules.
- pandas feature engineering over aggregate prescribing and public-health data.
- Transparent composite scoring instead of black-box clinical prediction.
- Streamlit dashboard UX for regional ranking, map exploration and selected-area review.
- Plotly visualisations for trends, score ranking and geographic context.
- Non-clinical prevention workflow prompts with explicit safety boundaries.
- Model-card, architecture and ethics documentation suitable for public GitHub review.

## What it proves professionally

- I can combine clinical pharmacy domain knowledge with product-minded analytics.
- I understand the difference between public-health planning support and clinical decision support.
- I can communicate data assumptions, risk-scoring limitations and governance needs.
- I can keep a portfolio MVP simple enough for a recruiter or technical reviewer to run locally.

## Interview talking points

- Why the demo uses synthetic aggregate data by default.
- How the risk score is computed and why it is intentionally interpretable.
- How the dashboard avoids individual advice, diagnosis and treatment recommendations.
- What governance would be required before adapting the idea to real aggregate open data.
- How the project could be extended with OpenPrescribing or OHID Fingertips connectors while keeping safe fallbacks.
